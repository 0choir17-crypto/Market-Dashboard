# 検証依頼: Market Regime 判定のしきい値

Market-Dashboard（日本株のマーケットコンディション画面）の `/` に、地合いを緑 / 黄 / 赤で出すカードを置いた。
判定のしきい値は**すべてたたき台**で、データで決めていない。Supabase の履歴を使って妥当な値を決めてほしい。

---

## 前提と制約

- **読み取り専用**。Supabase の本番テーブルに書き込まない・列を足さない・バッチを変えない。
- 結果はこのリポジトリ内のレポート（Markdown）とスクリプトとして残す。再実行できる形にする。
- 判定の目的は「**今日、新規の買いを積極的に入れてよい環境か**」を判断すること（米国株トレーダーの手法の日本株版。
  悪い環境では良い銘柄でも凡庸なトレードになるので、まず地合いを見る）。売買タイミングの予測ではない。
- 過剰適合を避ける。細かい格子で最良点を拾うのではなく、**成績が安定して良い「台地」の中央**を推奨値にする。
  前半で決めて後半で確かめる（時系列で分けた検証。ランダム分割はしない）。

---

## 1. 主導株（Liquid Leaders）— 最優先

### データ

| テーブル | 列 | 備考 |
|---|---|---|
| `liquid_leaders` | `date, code, tier, t21, t63, in_t21, in_t63` | PK `(date, code)`。1 行 = その日 t21 か t63 の一覧にいる銘柄。**2025-09 以降しか無い** |
| `liquid_leaders_sector` | `date, tier, sector_s33, n_t21, n_t63` | 業種別の件数。日ごとに足すと段の件数になる |

- `tier`: `large`（60 日売買代金 上位 200 位・ADR 2% 以上・t 2.0 以上で入る）/ `mid`（201〜1,000 位・ADR 3% 以上・t 1.5 以上で入る）。
  出る線はどちらも「入った後の t の最高値 − 1」。
- t21 / t63 = 自力の t 値（TOPIX につられた分を除いた強さの安定度。直近 21 日 / 63 日）。
- 履歴が約 14 か月しか無い。**一覧を作るバッチ（`scripts/daily/scan_liquid_leaders.py`）を過去に遡って再計算できるなら、
  10 年程度に伸ばしてから検証してほしい**（本番テーブルには書かず、手元で）。できなければ 2025-09 以降で行い、標本の少なさを明記する。

### 画面での計算（`lib/leaderState.ts` と完全に同じにすること）

段ごと、各営業日 D について:

- 営業日は `liquid_leaders` にある日付で数える。`P` = D から 5 営業日前（`LEADER_LOOKBACK = 5`）。
- `t21_now` = D で `in_t21 = true` の件数、`t21_prev` = P で同じ件数
- `entered` = D で `in_t21 = true` かつ P で `in_t21 = true` でない銘柄の数
- `exited` = P で `in_t21 = true` かつ D で `in_t21 = true` でない銘柄の数（D に行が無い銘柄も含む）
- `fade_pct` = D で `in_t63 = true` の銘柄のうち `in_t21 != true` の割合（%）。t63 の一覧が 0 件なら null
- `shrink_pct` = `(t21_prev − t21_now) / t21_prev × 100`（`t21_prev = 0` なら 0）

判定（上から順に評価）:

```
赤 … fade_pct ≥ FADE_BAD(50)
赤 … shrink_pct ≥ SHRINK_BAD(20) かつ exited > entered
緑 … t21_now ≥ t21_prev かつ entered ≥ exited かつ fade_pct < FADE_OK(30)
黄 … それ以外
```

「失速」を見る理由: 3 か月強い銘柄は初期から持つ大口が大きな含み益を抱えている。その銘柄が直近で TOPIX に負け始めるのは
利益確定の売りが出始めたサインで、指数の見た目が崩れるより先に出やすい、という仮説。**この仮説自体が成り立つかも確かめてほしい**。

### 検証すること

1. **結果変数**（D の引け時点で判定 → 翌営業日以降を見る）
   - TOPIX（`market_conditions.topix_price`）とグロース250（`growth_price`）の 5 / 10 / 20 営業日先リターン
   - 20 営業日先までの最大下落率（TOPIX・グロース250）
   - その段の主導株自身の 20 営業日先リターンの中央値（価格は手元の株価データから。無ければ省略可）
2. **色ごとの成績**: 各色の出現率、上の結果変数の平均・中央値・勝率、最大下落率の分布。
   緑 > 黄 > 赤 の順に成績がきれいに並ぶのが理想。並ばないなら、どこが逆転しているかを示す。
3. **しきい値の感度**: `FADE_OK` 20〜40、`FADE_BAD` 40〜65、`SHRINK_BAD` 10〜35、`LEADER_LOOKBACK` 3 / 5 / 10 を粗い刻みで振り、
   緑と赤の成績差が安定して大きい範囲を表で示す。
4. **先行性**: `fade_pct` が上がり始めてから、TOPIX の判定（下の 3. 指数）が赤になるまでの日数の分布。先行しないなら、そう書く。
5. **点滅の多さ**: 色が切り替わる回数 / 年、同じ色が続く日数の中央値。毎日のように色が変わるなら、
   しきい値に幅を持たせる（入るときと出るときで線を変える）案も比べてほしい。
6. **段の違い**: 大型と中小で推奨値を分けるべきか。

## 2. Market Breadth

### データ

`market_conditions` の `pct_above_sma20` / `pct_above_sma50` / `pct_above_sma150`（移動平均より上にある銘柄の割合、%）。
`pct_above_sma50` は長い履歴がある想定。20 / 150 は最近追加した列なので、履歴がどこから埋まっているか確認して明記する。

### 画面での計算（`lib/breadthState.ts`）

`v` = 当日の `pct_above_sma50`、`d` = `v` − 5 営業日前の値（`BREADTH_LOOKBACK = 5`。営業日は `market_conditions` の行で数える）。

```
v ≥ BREADTH_HOT(70)               … 黄「広範な強さ（伸び切り注意）」
BREADTH_MID(50) ≤ v < 70          … 緑「健全」。d ≤ −BREADTH_FLAT(2) なら 黄「健全だが低下中」
BREADTH_WEAK(30) ≤ v < 50         … 黄「まちまち」
v < 30                            … 赤「弱い・売られすぎ」。d ≥ +2 なら 黄「売られすぎから回復中」
```

### 検証すること

- 主導株と同じ結果変数・色ごとの成績・感度（`BREADTH_HOT` 60〜85、`BREADTH_MID` 40〜60、`BREADTH_WEAK` 15〜35、
  `BREADTH_FLAT` 1〜5、`BREADTH_LOOKBACK` 3 / 5 / 10）。
- **70% 以上を黄（伸び切り注意）にするのが妥当か**。70% 以上の日の先行リターンが 50〜70% の日より明確に悪くないなら、緑にすべき。
- 30% 未満の「売られすぎから回復中」（d ≥ +2）が、回復していない 30% 未満より先行リターンが良いか。
- 判定に 20 日線・150 日線を加えると成績が良くなるか（例: 50 日線が健全でも 20 日線が急落中なら黄）。加える価値が無ければそう書く。

## 3. 指数（TOPIX / 日経225 / グロース250）

### データ

`market_conditions` の `topix_price` / `nikkei_price` / `growth_price`（終値。列名は `*_close` ではない）。2008-05-08 以降。

### 画面での計算（`lib/trendState.ts`）

- EMA は先頭 `length` 本の単純平均を種にする（Pine 方式）。EMA9 / EMA21 を終値で計算。
- 向き = 今日の EMA と `SLOPE_LOOKBACK(5)` 本前の EMA の比較（上なら上向き）。

```
終値 > EMA21 かつ EMA21↑:
    終値 > EMA9 かつ EMA9↑ かつ EMA9 > EMA21 … 緑「上向き EMA9・21 の上」
    それ以外                                 … 黄「押し（上向き EMA21 は維持）」
終値 > EMA21 かつ EMA21↓                     … 黄「下向き EMA21 を上抜け（戻り売り待ち）」
終値 ≤ EMA21 かつ EMA21↑                     … 黄「上向き EMA21 を割り込み」
終値 ≤ EMA21 かつ EMA21↓                     … 赤「下向き EMA21 の下」
```

### 検証すること

- 5 つの状態それぞれの先行リターン・最大下落率（指数ごと）。
- **「上向き EMA21 を割り込み」は黄と赤のどちらに近いか**（先行成績が「押し」と「下向き EMA21 の下」のどちらに似ているか）。
- `SLOPE_LOOKBACK` 1 / 3 / 5 / 10 の比較。
- 3 指数の色が食い違う日（例: TOPIX 緑・グロース赤）の成績。どの指数を重く見るべきか。

## 4. 組み合わせ（余力があれば）

指数・Breadth・主導株の色を組み合わせた「総合の地合い」を作る価値があるか。
例: 3 つとも緑の日 / どれか 1 つが赤の日 の先行成績。単純な多数決で十分か。

## 納品物

1. レポート `reports/regime_thresholds.md`（場所はこのリポジトリの慣習に合わせてよい）
   - 冒頭に **推奨値の表**（下の定数名で。現行値・推奨値・根拠を 1 行ずつ）
   - 各節の色ごとの成績表、感度の表、標本数（日数）と期間
   - 結論が出ない・標本が足りない項目は、そう明記する（無理に値を出さない）
2. 再実行できるスクリプト一式
3. 推奨値の JSON（例）:

```json
{
  "leaders": { "large": { "FADE_OK": 30, "FADE_BAD": 50, "SHRINK_BAD": 20, "LEADER_LOOKBACK": 5 },
               "mid":   { "FADE_OK": 30, "FADE_BAD": 50, "SHRINK_BAD": 20, "LEADER_LOOKBACK": 5 } },
  "breadth": { "BREADTH_HOT": 70, "BREADTH_MID": 50, "BREADTH_WEAK": 30, "BREADTH_FLAT": 2, "BREADTH_LOOKBACK": 5,
               "hot_signal": "yellow" },
  "index":   { "SLOPE_LOOKBACK": 5, "below_rising_ema21_signal": "yellow" }
}
```

定数名は Market-Dashboard 側のコードと同じ（`lib/leaderState.ts` / `lib/breadthState.ts` / `lib/trendState.ts`）。
この JSON をそのまま Market-Dashboard 側に渡して反映する。
