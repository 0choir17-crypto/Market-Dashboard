# Market Dashboard デザイン方針（2026-09-05）

`WATCHLIST_JOURNAL_DESIGN.md` が「現状はこうなっている」を記録した文書であるのに対し、
これは「これからこう変える」を記録した文書。実装は Claude Code に委ねる前提で、
**判断の根拠と受け入れ条件**だけを書く。個別のコードは書かない。

対象は `/watchlist` を中心とするが、色とタイポグラフィと表は全ページ共通の層なので
サイト全体に及ぶ。

---

## 0. 参照点

改修の参照点は **TradingView のライトモード**。ただし「TradingView に似せる」のではなく、
TradingView が守っている次の規律を借りる。

- 色は意味を持つものにだけ付く。装飾としての色は無い
- 面は動かない。ホバーで浮いたり影が濃くなったりしない
- 一覧は少ない列で、深掘りは別の面（右パネル）で行う
- 見出しは小さく、データが主役

---

## 1. 監査で判明した事実

実装（`main` ブランチ）を走査した結果。方針の前提になるので先に置く。

| 事実 | 数値 | 出所 |
|---|---|---|
| `:root` の CSS 変数 | 17 個 | `app/globals.css` |
| ハードコードされたユニーク色 | **87 個** | `app` / `components` / `types` |
| 色定義が集中しているファイル | `types/watchlistJournal.ts` 39、`types/marketLeaders.ts` 34、`types/earningsQuality.ts` 32、`types/structurePivotEvents.ts` 27 | |
| 「良い状態」を表す緑 | **4 種類**（`#dcfce7`/`#15803d`、`#dcfce7`/`#166534`、`#bbf7d0`/`#14532d`、`#86efac`/`#14532d`） | 画面ごとに独立 |
| 琥珀 `#fef3c7`/`#92400e` の意味 | **3 通り**（警戒 / 中間スコア / 未整理） | Leaders / Earnings・Sectors / Watchlist |
| `min-w-[...]` を持つ表 | 7 つ（1500 / 1360 / **1320** / 1200 / 1100 / 980 / 900 px） | 全ページで横スクロール |
| `SortTh` の独立定義 | 3 箇所 | Sectors / Earnings / Leaders |
| ソート state を持つコンポーネント | 8 個 | |

**結論**: `/watchlist` 固有の問題はほとんど無い。色・タイポ・表という 3 つの共通層が
存在しないまま各画面が個別に解いてきた結果が、画面ごとの不一致として出ている。
したがって改修は画面単位ではなく層単位で行う。

---

## 2. 設計原則

以下 4 つを、個別の判断が割れたときの上位ルールとする。

1. **色は意味にだけ付ける。** 装飾・分類・見た目の変化のために色を使わない
2. **面は静止する。** ホバーで動く・浮く・影が変わる要素を置かない
3. **一覧は比較のため、詳細は決断のため。** 横断比較しない数値を一覧に置かない
4. **階層は余白と文字サイズで作る。** 罫線・枠・背景色を階層表現に使わない

## 3. 色

### 3.1 語彙を 7 つに固定する

色そのものではなく**意味**に名前を付け、`globals.css` の `:root` に置く。
各語彙は `bg` / `fg` / `border` の 3 値を持つ。

| トークン | 意味 | 使用例 |
|---|---|---|
| `--sem-strong` | 強い・良い・保有中 | HOLD、機関買い継続、スコア上位 |
| `--sem-ok` | 通常・許容範囲 | 通常上昇、スコア中上位 |
| `--sem-watch` | 警戒・要注意 | 出来高警戒、鮮度 aging |
| `--sem-weak` | 弱い・悪い | SHORT、出来高枯渇、鮮度 old |
| `--sem-idle` | 未評価・未整理・無彩色 | OTHERS、INBOX、SECOND、欠損 |
| `--sem-archive` | 済み・対象外 | SOLD |
| `--sem-focus` | 注目・選択中 | READY、リンク、ソート中の列 |

**重要な移動**: `OTHERS`（未整理）は現在 `--sem-watch` 相当の琥珀だが、**`--sem-idle`（無彩色）へ移す**。
未整理は警戒ではない。これで琥珀が「警戒」の一語だけを指すようになる。
`SECOND`・`INBOX` も同様に `--sem-idle` に寄せる。

同じ理由で、現在の `--neutral-color: #92400e` / `--neutral-bg: #fef3c7` は**廃止**する。
中立を名乗るトークンが琥珀であること自体が語彙の破綻。

### 3.2 損益色は語彙から独立させる

`--positive` / `--negative`（`#16a34a` / `#dc2626`）は意味語彙とは別系統として維持する。
数値の符号に付く色であり、状態を表す色ではないため。この 2 色が画面上で最も速く目に入る
状態を保つことが、色を減らす最大の目的。

### 3.3 状態バッジを廃止する

`/watchlist` の Current State は既に state でグループ化されている。
その中の全行に同じ色のバッジを置くのは同じ情報の二重描画。

- グループ見出しは **11px のミュートなテキスト + 件数**（色なし、折りたたみ矢印付き）
- `READY` のみ、行の**左端 2px のレール**（`--sem-focus`）で重みを表す
- Missed Board の `From` 列はバッジではなくテキスト。`READY` 由来の行だけ同じレール

結果として `/watchlist` の有彩色は、損益の緑赤・`--sem-focus` の青・鮮度バッジの 3 系統になる。

### 3.4 鮮度バッジ

判定ロジックと文言（断定しない）は現状のまま維持する。判断は正しい。
配色だけ変更する。

- `ok` は**無色**にする（グレーの点 + 時刻のみ）
- `aging` で初めて `--sem-watch`、`old` で `--sem-weak`

正常が目立たない状態を作ることが、異常の発見を速くする。

### 3.5 絵文字を色の代替に使わない

`types/sectorSelection.ts` の `🟢` / `⚪` / `🔴`、`PageHeader` の `📌` は削除し、
トークン化された色か Tabler 相当のアイコンに置き換える。
絵文字は環境ごとに字形とサイズが変わるため、密度の高い表で位置が揃わない。

### 3.6 受け入れ条件

- `types/*.ts` の生 16 進カラーが 0 になっている（チャート描画ライブラリに渡す値を除く）
- `app` / `components` / `types` のユニーク色が 87 → **20 以下**
- 同一の意味に対して 2 つ以上の色が使われている箇所が無い

## 4. タイポグラフィ

### 4.1 現状と問題

| 用途 | 現状 | 問題 |
|---|---|---|
| 欧文 | Sora（Google Fonts） | ジオメトリック・サンセリフ。見出し／ブランド向けで、字幅が広く小サイズの可読性が低い。数字が特に広く、密度が出ない |
| 和文 | Noto Sans JP | 妥当。維持 |
| 数値 | IBM Plex Mono | 全数値に適用されており画面が重い。等幅の必要は本来「識別子」にしか無い |

3 書体を webfont で読んでいる分のコストもかかっている。

### 4.2 方針：TradingView のスタックに合わせる

TradingView の既定フォントスタックは以下（Lightweight Charts の `LayoutOptions.fontFamily`、
および Advanced Charts の既定値として公開されている）。Pine Script の `font.family_default`
も Trebuchet MS を指す。

```
-apple-system, BlinkMacSystemFont, "Trebuchet MS", Roboto, Ubuntu, sans-serif
```

これを欧文・数値の主スタックとし、末尾に和文を接続する。

```
--font-sans:
  -apple-system, BlinkMacSystemFont, "Trebuchet MS", Roboto, Ubuntu,
  var(--font-noto), sans-serif;
```

副次効果として **Sora と IBM Plex Mono の webfont 読み込みが消える**（欧文はすべてシステムフォント）。
`next/font` の設定から Sora を外し、Plex Mono は 4.4 の用途のためだけに残す。

### 4.3 必須の検証：桁揃え

**Trebuchet MS は 1996 年の TrueType で、OpenType の `tnum`（tabular figures）機能を持たない
可能性が高い。** その場合 `font-variant-numeric: tabular-nums` は無言で無効化され、
表の数字の桁がずれる。採用前に必ず次を確認すること。

> 検証手順: Trebuchet MS で `0123456789` と `1111111111` を同サイズで描画し、
> 幅が一致するか測る。一致すれば既定で等幅数字なので `tnum` は不要。

- 一致する場合 → そのまま採用
- 一致しない場合 → **代替として IBM Plex Sans を採用**する。既に Plex Mono を導入しているので
  ファミリーが揃い、`tnum` を正式にサポートしている。TradingView への見た目の近さは
  Trebuchet MS に劣るが、**桁が揃わない表は方針 3 に反するため桁揃えを優先する**

### 4.4 等幅を使う範囲を限定する

等幅は「文字単位で読む識別子」にのみ使う。

| 用途 | 書体 |
|---|---|
| 銘柄コード（`5367`） | 等幅（IBM Plex Mono） |
| 日付・時刻 | 等幅 |
| 価格・率・日数・スコア等の**すべての数値** | サンセリフ + `tabular-nums` |

現在 `globals.css` で `tabular-nums` が `.font-mono` に結びついているため、
mono を外すと桁揃えも同時に失われる。**先に `.num` クラスとして `tabular-nums` を切り出す**こと。
これは 4.2 より前に行う。

### 4.5 サイズとウェイトのスケール

段階を減らす。以下の 5 段のみとし、それ以外を使わない。

| 段 | px | 用途 |
|---|---|---|
| caption | 11 | グループ見出し、注記、単位、列見出し |
| small | 12 | 銘柄名、セクター、補助数値 |
| body | 13 | 表のセル本体 |
| lead | 15 | セクションの主数値 |
| title | 18 | ページタイトル |

ウェイトは **400 と 500 の 2 つだけ**。`font-bold`（700）は使わない。
現在の `PageHeader` は `text-2xl font-bold`（24px / 700）なので **18px / 500** に下げる。
ページタイトルはナビゲーションで既に分かっており、大きくする必要が無い。

セクション見出し（`Current State` / `Missed Board`）は caption 段の
**ミュートなラベル + 件数**とする。主役はデータ。

## 5. 表

### 5.1 一覧に置く列を絞る

現在の Current State 15 列のうち、`ATR14` / `1R` / `RR2` / `RR2 %` / `Ext R` / `ADR %` は
**22 行を横断比較するための数値ではなく、1 銘柄を決めるための数値**。原則 3 に反する。

- **要約ビュー = 7 列**: `Code / Name` / `Days` / `Price` / `Return` / `1R %` / `RS` / `52W High`
- 残り 8 列は**行クリックで開く詳細行**に格納する
- ヘッダーに `要約 / 全 15 列` のトグルを置き、従来の使い方も残す

要約ビューは `min-w` を持たず、横スクロールを出さないことを条件とする。

### 5.2 共通コンポーネントに集約する

`SortTh` が 3 箇所、ソート state が 8 コンポーネントに分散している。
`components/shared/DataTable.tsx`（仮称）に以下を集約する。

- 列見出しのソート UI（`↑` / `↓` / `↕`、ソート中は `--sem-focus`）
- NULL を昇順・降順いずれでも末尾に置くソート規則（現行の判断を維持）
- グループ化と折りたたみ
- 要約 / 全列トグルと詳細行

**この順序が重要**: `/watchlist` を先に個別対応すると 4 つ目の方言が増えるだけになる。
共通化してから `/watchlist` を移す。移し終えれば Earnings 1500px・Leaders 1360px にも
同じ改善が自動的に及ぶ。

### 5.3 セルの表示規則

| 項目 | 方針 |
|---|---|
| `Entry → Now` | 矢印をやめ `4,250 / 4,110` とし、エントリー値をミュートで従属させる。現在値が主 |
| `Days` / `Stay` | 単位は**見出しが持つ**（`Days (営業)` / `Stay (暦)`）。セルの値からは「日」を落とす |
| 数値 | 右揃え + `tabular-nums`。率は 1 桁、`1R %` / `RR2 %` は 2 桁（TradingView と突き合わせるため。現行維持） |
| 欠損 | `—` を `--sem-idle` の文字色で。0% として扱わない（現行維持） |
| `1R %` / `RR2 %` | 中立色。損益色を当てない（現行の判断を維持。理由も現行文書のとおり） |

### 5.4 行の密度

- 行高 32px、セル padding 縦 8px / 横 10px
- 行間の区切りは 0.5px の `--border` のみ。ゼブラストライプは使わない
- ホバーは背景色の変化のみ。移動・影の変化は行わない

## 6. 面・枠・影

`globals.css` の `.card` は現在こうなっている。

```css
.card:hover { box-shadow: 0 4px 12px rgba(0,0,0,.1); transform: translateY(-1px); }
```

これはマーケティングサイトの仕草であり、原則 2 に反する。**ホバーの `transform` と
`box-shadow` の変化を削除**する。静止時の `box-shadow: 0 1px 3px` も削除し、
面の分離は背景色差と 0.5px の罫線だけで行う。

### 背景

`--bg-primary` と `--bg-card` が同値（`#fdf6e3`）のため、テーブルが背景に沈んでいる。

- `--bg-primary` はクリームを維持する（この画面の「自分のノート」という性格は正しい）
- `--bg-card` を**白に分離する**（`#fffdf7` 前後。純白だとクリームとの差が強すぎる場合は調整）
- 上記の影の削除と**必ずセットで**行う。影を残したままカードを白くすると浮きすぎる

罫線は 1px → **0.5px**、`--border` は現状の `#e6dcc0` からもう一段淡くする。

## 7. 実施順

層の依存関係があるため、この順序を守る。

| # | 内容 | 範囲 | 目安 |
|---|---|---|---|
| 0 | `.num` クラスの切り出し（`tabular-nums` を `.font-mono` から分離） | `globals.css` | 数行 |
| 1 | 意味語彙 7 トークンの定義と `types/*.ts` 4 ファイルの置換 | 全ページ | 中 |
| 2 | フォントスタック変更（4.3 の検証を先に実施） | 全ページ | 小 |
| 3 | `.card` の影・ホバー削除、`--bg-card` 分離、罫線 0.5px | 全ページ | 小 |
| 4 | タイプスケール適用（`PageHeader` を 18px / 500 へ） | 全ページ | 小 |
| 5 | 状態バッジ廃止 → グループ見出し + `READY` レール | `/watchlist` | 中 |
| 6 | `DataTable` 共通化（ソート・グループ・要約/全列・詳細行） | 全ページ | 大 |
| 7 | Current State を 7 列 + 詳細行へ移行 | `/watchlist` | 中 |
| 8 | Missed Board サマリを水平 1 行へ（件数のみ表示、中央値は選択中の 1 組を下に大きく） | `/watchlist` | 小 |

0〜4 が終わった時点で一度手を止め、画面を見てから 5 以降を判断すること。
色とフォントを整えた状態で表を見ると、どの列が本当に要るかの判断が変わる可能性が高い。

## 8. この改修で「やらないこと」

現行文書 9 章の判断は**すべて維持する**。特に以下は今回も追加しない。

- 勝率・PF・期待値のタイル（サンプル過少。中央値までに留め件数を明記する方針を維持）
- 8% ルールの色・印（`1R %` は中立色のまま）
- 「自力発見」ラベル / `scanner_names` 列
- 日付ピッカー
- 追加・編集・削除の導線

加えて、今回新たに見送るもの。

| 見送るもの | 理由 |
|---|---|
| **ダークモード** | クリーム背景という方向性と競合する。2 系統のトークンを維持する負担が、色を 20 以下に絞る作業と衝突する。語彙が固まってから別途検討する |
| **`SOLD` を Current State から出す** | 目的 1（拾った銘柄はどういう姿だったか）にとって SOLD は資産。問題は記録開始前の建玉 4 銘柄（3697 / 5857 / 6326 / 8136）が混ざることだけなので、その 4 行に注記マークを付けて解決する |
| **チャートの埋め込み** | 深掘りは TradingView 側で行うという現行の分業を崩さない |

- [ ] `SortTh` の定義が 1 箇所
- [ ] 鮮度バッジの判定ロジックと文言が変わっていない
