# 押し目深度 → 再ブレイク難易度の検証

**問い: 高値からの押しが何％下落したら、その高値の再ブレイクが困難になるか。**

`chart_ohlcv_cache` の日足全履歴から実測する検証スクリプト。ダッシュボード本体には手を入れない、読み取り専用のオフライン解析。

## 実行

```bash
# セルフテスト（DB 不要。ロジックが壊れていないかを合成データで確認）
npx tsx scripts/analysis/pullbackRebreak.selftest.ts

# 本番実行（.env.local の NEXT_PUBLIC_SUPABASE_* を自動ロード）
npx tsx scripts/analysis/pullbackRebreak.ts

# 銘柄を絞って試す / 結果をファイルに出す
npx tsx scripts/analysis/pullbackRebreak.ts --limit-codes 100
npx tsx scripts/analysis/pullbackRebreak.ts --segments adr,trend --out .analysis/pullback
```

主なオプションは `pullbackRebreak.ts` 冒頭のコメント参照。既定値は `DEFAULT_PARAMS`（`pullbackRebreakCore.ts`）。

## 何をどう測っているか

### エピソードの定義

1. 走行高値を更新し続ける。**起点の高値**として認めるのは「直近 60 本の最高値」かつ「20日平均売買代金 ≥ 1億円」のものだけ（ミクロな高値と低流動性を排除）。
2. その高値から **3%** 下げたら「押し」開始。
3. 押し幅（高値からの下落率）を追い、**終値が高値を上抜けたら再ブレイク成功**として確定。
4. 高値から 500 営業日たっても戻せなければ失敗として打ち切り、そこから次の高値探索を再開。

価格基準は既定で終値（`--basis close`）。`--basis hl` にすると高値/安値ベースになり、押しは深く・再ブレイクは早く出る。

### 集計はハザード（生存）型

素朴に「エピソードの最終的な押し幅ごとに再ブレイク率を出す」と結果が歪む。浅い押しで終わったエピソードは「浅いうちに戻れた成功例」に偏り、深いバケットには失敗例だけが残るため（結果で条件付けたバイアス）。

そこでこのスクリプトは、閾値 `d` ごとに

> 「押しが `d` まで達した」エピソードを母集団とし、**`d` に達した日を起点に** H 営業日以内の再ブレイク率を測る

という形で集計する。これにより

- 母集団が「いま `d` まで下げている銘柄」= 実際に判断を迫られる場面と一致する
- 深い押しほど到達までに時間を食う、という機械的な不利が消える（起点が揃う）

ので、`d` を横軸に並べた曲線がそのまま難易度カーブになる。

### 打ち切り（censoring）

`d` 到達から H 本ぶんのデータが無いケース（データ末尾・エピソード打ち切り）を「失敗」に数えると再ブレイク率が過小に出る。観測できたかを判定し、未観測は分母から外して `打切` 列に計上する。**`打切` が大きい列の数字は割り引いて読むこと。**

## 出力の読み方

| 列 | 意味 |
| --- | --- |
| `押し>=` | 押し深度の閾値（`%` 軸と `×ADR` 軸の 2 種類を出す） |
| `n` | その深さまで下げたエピソード数（累積） |
| `深化` | そこから 1 段深い閾値まで下げてしまった割合。**引き返せなくなる点**の目安 |
| `<=Nd` | その深さに到達した日から N 営業日以内に再ブレイクした割合 |
| `中央日数` | 到達日から再ブレイクまでの営業日数の中央値（戻せた例のみ） |
| `確定率` | 再ブレイク後 5 営業日、終値が高値の上に留まれた割合（ダマシでない割合） |
| `打切@Nd` | 判定に足るデータが無かった割合 |

数字に付く `?` は母数 30 件未満。表の下に出る `>>` 行が結論の要約で、

- 再ブレイク率が 50% を割る深さ（＝ここから分の悪い賭けになる）
- 1 段深くなるごとの劣化が最大だった区間（＝実質的な分水嶺）

を拾う。

### 2 つの深度軸を必ず見比べる

`%` 軸だけで見ると「ADR 6% の銘柄の 15% 押し」と「ADR 2% の銘柄の 15% 押し」が同じ扱いになるが、この 2 つはまったく別物。`×ADR` 軸（押し幅 ÷ 高値時点の ADR）のカーブのほうが折れ点がはっきり出るなら、**閾値は「％」ではなく「ADR の何倍か」で持つべき**という結論になる。`--segments adr` でボラ帯別のカーブも出せる。

### 「戻せるか」と「戻すのにいくらかかるか」は別問題

`<=Nd` が横ばいでも `中央日数` が伸びていれば、それは「戻せなくなる」のではなく「戻すのに時間がかかる」。資金効率の観点では後者も十分に不利なので、両方見て判断する。`確定率` が落ちていく深さは「戻しても続かない（ダマシになる）」領域。

## 既知の限界

- `chart_ohlcv_cache` の株価が分割・併合調整済みである前提。未調整データを掴んだ場合に備え、前日比 ±50% 超の足はデータ断絶とみなして状態をリセットするガードを入れてあるが、小さな未調整は検出できない。
- ユニバースは既定で `chart_ohlcv_cache` に載っている銘柄。これは閲覧実績のある銘柄に偏る可能性があり、厳密なユニバースを組みたい場合は `--universe daily_signals` か `--codes` を使う。
- 生存バイアス: 上場廃止銘柄がテーブルに無ければ、深い押しの失敗例が過少になる（＝深い押しの再ブレイク率が実態より高く出る）方向に効く。
- 市場地合い（`market_conditions`）では層別していない。`--segments year` が地合いの代理になる。
